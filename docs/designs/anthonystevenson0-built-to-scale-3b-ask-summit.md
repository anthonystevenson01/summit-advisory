## 0. Shape of the change

The third card on `/tools` becomes a form. A prospect gives a website address, up to three documents and a company email; the browser uploads the files straight to Vercel Blob under a server-issued token; the submit route stores a request record, enqueues one QStash message, and sends a confirmation with a two working day turnaround. QStash calls the processing route, which verifies the signature and runs six stages under a stage clock inside a 300 second function: crawl the site politely, pull text from the documents, draft the five Built to Scale? parts with one extraction call (PDFs sent to the model as files), score the draft through the existing `scoreModel`, create a draft report through the Release 4 `createReport`, and notify Anthony. The Release 4 editor gains a "Drafted inputs" section (shown only when the report carries `askRequestId`) with the drafted parts, their confidence and evidence, the crawled page list and the document names, and a "Re-run with these inputs" button. An admin queue lists requests with a pause switch; a daily cron deletes uploads and crawled pages after 30 days; the delete-my-data link covers requests; the daily report emails a spend alert once a month when the threshold is passed. The prospect never sees the raw run: the report Anthony publishes is what they receive, by his hand, not the system's.

## 2. Integration Points

### 2.1 Validation (`validation.ts`)

- `validateWebsiteUrl(value)` → `{ ok: true, url, host } | { ok: false, error }`. Trims; prefixes `https://` when no scheme; parses with `URL`; requires `http:` or `https:`, no username or password, a hostname containing a dot that is not an IP literal, not `localhost`, not ending `.local`, `.internal` or `.localhost`, length at most 2,048; lowercases the host; drops the fragment; keeps the query on the start URL only. Error strings in `copy.ts` (`URL_MESSAGE`).
- `hostOf(url)` and `isSameHost(a, b)`: hostnames compared lowercase after stripping one leading `www.` (assumption 4.5).
- `isEmailShaped(value)`: one `@`, a dot in the domain, no spaces, under 254 characters (the 1b gate's rule).
- `FREE_MAIL_DOMAINS`: gmail.com, googlemail.com, outlook.com, hotmail.com, hotmail.co.uk, live.com, msn.com, yahoo.com, yahoo.co.uk, ymail.com, icloud.com, me.com, mac.com, proton.me, protonmail.com, pm.me, aol.com, gmx.com, gmx.de, mail.com, zoho.com, yandex.com, fastmail.com, hey.com. `validateCompanyEmail(value)` → `{ ok: true, email, domain, emailHash? }`: shaped, domain not in the list (exact match, lowercase), else `FREE_MAIL_MESSAGE`: "Please use a company email address. Free mail addresses such as Gmail, Outlook, Hotmail, Yahoo, iCloud and Proton are not accepted for this request, because Summit commits a person's time to each one." The hash is computed by the caller through `hashEmail` (the pure module does not import `node:crypto`).
- Files: `ALLOWED_FILE_TYPES` is a table of three entries `{ type: "pdf" | "pptx" | "docx", extension, contentType, magic }` (PDF `%PDF-`; the two Office types share the zip signature `PK\x03\x04`). `fileTypeFromName(name)` by extension (case insensitive, the last extension only). `sniffFileType(bytes, name)`: `%PDF-` with a `.pdf` name is `pdf`; the zip signature with a `.docx` or `.pptx` name is that type (the office extractor confirms the entry names later); anything else null. `validateFileMeta(files)` on the submitted `{ name, pathname, url, size, contentType }` list: at most `MAX_FILES`, each name 1 to 200 characters with a known extension, size 1 to `MAX_FILE_BYTES`, `contentType` in the table or `application/octet-stream` (some browsers send it for Office files), names unique. Errors in `copy.ts` (`FILE_TYPE_MESSAGE`, `FILE_SIZE_MESSAGE`, `FILE_COUNT_MESSAGE`).
- `REQUEST_ID_PATTERN` `^ask_[0-9a-f]{16}$`; `isAskRequestId`; `uploadPrefixFor(id)` is `ask-summit/{id}/`; `isUnderPrefix(pathname, id)` requires the prefix and exactly one more segment with no `..`.

### 2.2 Crawl rules (`crawl-rules.ts`) and the crawler (`crawler.ts`)

- `parseRobots(text | null, token)` → `RobotsRules { allow: string[], disallow: string[], crawlDelayMs: number }`. Lines are split, comments after `#` dropped, keys matched case insensitively. Groups are `User-agent:` lines followed by rules; a group whose agent token contains `summitbot` (case insensitive) wins over `*`; no group means allow everything; null text (no robots.txt, or a non-200) means allow everything. A pattern is a path prefix; `*` and `$` are not interpreted: the prefix is the pattern up to the first `*` (assumption 4.6). `Crawl-delay` is read in seconds and capped at 5,000 ms.
- `isAllowed(rules, path)`: the longest matching prefix among allow and disallow decides; a tie goes to allow; no match allows. An empty `Disallow:` is ignored.
- `normaliseLink(href, base)` → absolute URL string or null: resolves against `base`; `http` or `https` only; same host (`isSameHost`); drops the fragment and the query; strips a trailing slash except on the root; rejects paths ending in a file extension from a short list (pdf, jpg, jpeg, png, gif, svg, webp, zip, xml, css, js, ico, mp4, mp3, woff, woff2, doc, docx, ppt, pptx, xls, xlsx); rejects `mailto:`, `tel:`, `javascript:`, `data:`.
- `scorePage(path, title)` → integer: the start URL is given 100 by the crawler; otherwise a sum over keywords found in the lowercased path segments or title: product, products 5; pricing, plans, plan 5; customers, customer, case-study, case-studies, casestudy, case study (title), testimonials, success 4; about, about-us, company 4; team, leadership, people, founders 3; solutions, solution, platform, features, how-it-works 3; industries, use-cases, usecases, services 2; blog, news, press, careers, jobs, legal, privacy, terms, cookie, cookies, login, signin, signup, register, account, cart, search, tag, category, author, page −3 each; minus one per path segment beyond the second. Ties break by discovery order.
- `stripVisibleText(html)` → `{ title, text }`: removes HTML comments; removes `script`, `style`, `noscript`, `template`, `svg`, `iframe`, `head` blocks; removes `nav` and `footer` blocks and elements carrying `role="navigation"` or `role="contentinfo"` or `aria-hidden="true"` (where identifiable by a simple tag scan; nested same-name tags are not balanced, which is accepted); turns block tags (`p`, `div`, `br`, `li`, `h1` to `h6`, `tr`, `td`, `th`, `section`, `article`, `header`, `blockquote`, `pre`, `table`, `ul`, `ol`, `dd`, `dt`) into newlines; strips remaining tags; decodes named entities (`amp`, `lt`, `gt`, `quot`, `apos`, `nbsp`, `copy`, `reg`, `trade`, `hellip`, `mdash` to ", ", `ndash` to ", ") and numeric entities; collapses runs of spaces and tabs to one space and runs of newlines to two; trims; caps at `PAGE_TEXT_CAP` on a word boundary. The title is the `<title>` text, trimmed, 200 characters.
- `extractLinks(html)` → `string[]` of `href` values from `<a>` tags, in order, deduplicated, before normalisation.
- `CrawledPage { url, path, title, chars, score, status, text }`; `CrawlStore { host, startUrl, fetchedAt, userAgent, robots: "fetched" | "missing" | "error", crawlDelayMs, pages: CrawledPage[], skipped: { disallowed, offHost, failed, timedOut, notHtml, duplicate }, truncated: boolean, totalChars }`. The page list the editor shows is `pages` without `text` (the store's `getPages(id, { withText: false })`).
- `crawlSite(startUrl, { deadlineAt, userAgent })`: section 3.4.

### 2.3 Office text (`office-text.ts`)

- `textFromDocumentXml(xml)`: finds every `<w:p ...>...</w:p>` block in order; inside each, concatenates the content of every `<w:t ...>...</w:t>` run (runs are joined with nothing between them, which is how Word splits words across runs; `xml:space="preserve"` is irrelevant to the join), turns `<w:tab/>` into a space and `<w:br/>` into a newline, skips runs inside `<w:del>` (tracked deletions), decodes XML entities (`amp`, `lt`, `gt`, `quot`, `apos`, numeric), and joins paragraphs with one newline. Whitespace within a paragraph is collapsed. Table cells are paragraphs too (`w:p` inside `w:tc`) and so come out one per line.
- `textFromSlideXml(xml)`: the same over `<a:p>` and `<a:t>`, with `<a:br/>` as a newline.
- `orderSlideEntries(names)`: the names matching `^ppt/slides/slide(\d+)\.xml$` sorted by the number; `_rels` and notes are excluded.
- `extractDocxText(bytes)` → `{ text, parts: 1, truncated }`: `unzipSync` with a filter that keeps `word/document.xml` only; a missing entry throws `OfficeTextError("not a DOCX: word/document.xml missing")`; an `unzipSync` throw is wrapped as `OfficeTextError("not a zip archive")`. `extractPptxText(bytes)` → `{ text, parts: n, truncated }`: the filter keeps `ppt/slides/slide*.xml`; none throws `OfficeTextError("not a PPTX: no slides")`; each slide is rendered as `Slide {n}` on a line, its text, then a blank line. Both cap the text at `OFFICE_TEXT_CAP` on a word boundary with `truncated: true`. Images, charts and embedded objects are ignored (risk 7.8).

### 2.4 Extraction schema, parser and placeholder rule (`extraction-schema.ts`)

`extractionSchema()` returns a `NamedSchema` (`name: "ask_summit_extraction"`, `strict: true`): object, `additionalProperties` false, required `companyName`, `summary`, `parts`.

- `companyName` string, description "The company's name as the material gives it; empty when the material does not say."
- `summary` string, "Three to five sentences on what the company sells, to whom and how, drawn only from the material; British spelling; no dashes."
- `parts` object, `additionalProperties` false, required the five keys in method order; each an object, `additionalProperties` false, required `text`, `evidence`, `confidence`, `reason`: `text` string "The drafted part in the voice of a founder describing their own business, 40 to 2000 characters when the material supports it, or an empty string when it does not; {the part's prompt line from BTS_PARTS}"; `evidence` array of strings, `maxItems` 2, "One or two short snippets quoted verbatim from the material that support the text; empty when text is empty"; `confidence` enum low, medium, high; `reason` string "Under 25 words on why that confidence, naming what the material lacked when it is low".

`parseExtraction(raw)` → `ExtractionResult { companyName, summary, parts: Record<BtsPartKey, DraftedPart> }` with `DraftedPart { text, evidence: string[], confidence, reason }`: object check; `parts` must be an object; every one of the five keys must be present and an object (missing throws `SchemaError` naming it); any other key under `parts` throws; `text` must be a string (empty allowed), trimmed, cut to `PART_MAX` at the last space; `evidence` filtered to strings, trimmed, non-empty, the first `EVIDENCE_MAX` kept, each cut to `EVIDENCE_CHARS` at a word boundary; `confidence` must be in the enum; `reason` trimmed or `""`; `companyName` trimmed, 120 characters; `summary` trimmed, `SUMMARY_CHARS`.

`thinPlaceholder(part)`: "The material Summit was given did not cover {part label}. Treat this part as absent and score it as such." (over 40 characters for every label; tested). `partsForScoring(parts, edits?)` → `PartsRecord`: for each key, the edited text when `edits[key]` is a string, else the drafted `text`; trimmed; when the result has fewer than `PART_MIN` characters it becomes the text (when non-empty) followed by a space and the placeholder, or the placeholder alone; cut to `PART_MAX`. This is the placeholder rule (AC4 d) and it runs before `validateParts` in both the processing stage and the rerun route, so a blank part never fails validation.

### 2.5 The extraction prompt (`extraction-prompt.ts`)

`EXTRACTION_SYSTEM_PROMPT`, in order: the role ("You prepare the inputs for Summit Strategy Advisory's Built to Scale? assessment from a company's website pages and documents."); the five parts, each as `{key}: {name}. {prompt}` from `BTS_PARTS`; the house rules: write each part as the founder would describe their own business, in the first person plural; use only what the material says and do not invent, infer beyond it or fill gaps with industry norms; quote evidence verbatim from the material, one or two short snippets per part; when the material is thin for a part return low confidence and say what is missing in the reason; when the material says nothing usable for a part return an empty text with low confidence; numbers only when the material gives them; British spelling; no em or en dashes, no hyphen used as a dash; no hype words; the company name as the material gives it, empty when unknown; return the JSON object only. The prompt is a constant in code because the owner has not written a Notion row for it; the runbook names the move as a follow-up (section 6).

`buildExtractionUser(material)` with `ExtractionMaterial { host, pages: Array<{ url, title, text }>, docs: Array<{ name, kind: "text" | "pdf" | "rejected", text?: string, reason?: string }> }`: a header line "Company website: {host}"; "## Website pages" then each page as `[Page {n}: {url}] {title}` on one line followed by its text; "## Documents" then each text document as `[Document: {name}]` followed by its text, each PDF as `[Attached PDF: {name}, sent as a file]`, each rejected document as `[Document: {name}, not readable: {reason}]`; when there are no pages and no documents, one line "No material could be read; return empty parts with low confidence." Pages are in the order given (the crawler stores them by score, start page first). The total output is held under `EXTRACTION_TEXT_BUDGET` characters by trimming the longest page texts first: the budget less the fixed lines is shared so that no single page exceeds `budget / max(pages, 4)` and documents keep up to 40 percent of the budget; a trimmed page ends with " [cut]". The function is pure and the test pins the labels and the cap.

### 2.6 The stage clock (`stage-clock.ts`)

`STAGES`: `crawl`, `documents`, `extraction`, `scoring`, `report`, `finish`. `STAGE_PLAN` (milliseconds): crawl cap 100,000, min 20,000; documents cap 40,000, min 10,000; extraction cap 60,000, min 56,000; scoring cap 120,000, min 60,000; report cap 5,000, min 3,000; finish cap 3,000, min 1,000. `PROCESS_BUDGET_MS` is 290,000 so the route always answers inside `maxDuration = 300`.

`createStageClock(startedAtMs)`: `allowance(stage, nowMs)` is `min(cap, PROCESS_BUDGET_MS - elapsed - sum of the minimums of every later stage)`; when that is below the stage's minimum it throws `StageTimedOutError(stage, "ran out of time before {stage}: {remaining} s left, {min} s needed")`. `start(stage)` and `finish(stage)` record one timing per stage; `timings()` returns `{ crawl, documents, extraction, scoring, report, finish, total }` in ms (zero for a stage never started). `deadlineFor(stage, nowMs)` is `nowMs + allowance`. The minima are what each stage needs to be worth starting: extraction's 56 s is one `callModel` attempt (40 s) plus one retry inside the first 15 s, since the call cannot be cut short; scoring's 60 s is the children's worst case plus a margin, after which `scoreModel`'s own deadline race protects the synthesis. The sum of the minima is 150 s, so the crawl can always use its full 100 s and the clock never starves a later stage on a normal run. Typical timings: crawl 15 to 40 s, documents 2 to 8 s, extraction 15 to 35 s, scoring 25 to 50 s, report under 1 s.

### 2.10 Spend (`spend.ts`)

## 3. Data Flow

### 3.1 The upload token route (`POST /api/ask-summit/upload`)

1. `isPaused()`: when paused, 503 with the paused message (no token while paused).
2. `isBlobConfigured()` false: 503 "uploads are not configured" (logged once).
3. `body = await req.json()`; `handleUpload({ body, request, onBeforeGenerateToken, onUploadCompleted })`.
4. `onBeforeGenerateToken(pathname, clientPayload)`: parse `clientPayload` as JSON for `requestId`; `isAskRequestId` else throw (the SDK turns the throw into a 400); `isUnderPrefix(pathname, requestId)` else throw; the file name segment passes `fileTypeFromName` else throw with `FILE_TYPE_MESSAGE`; `incrementUploads(requestId)` above `MAX_FILES` throws with `FILE_COUNT_MESSAGE`; return `{ allowedContentTypes: the three types plus application/octet-stream, maximumSizeInBytes: MAX_FILE_BYTES, addRandomSuffix: true, validUntil: now + 15 minutes, tokenPayload: JSON of { requestId } }`.
5. `onUploadCompleted`: logs the pathname and size only. Nothing depends on it (it does not fire locally).
6. Respond with the SDK's JSON. Errors from the SDK are answered 400 with the thrown message when it is one of the copy messages, else "Upload could not be authorised." The route never logs a URL with a token in it.

The token therefore restricts content types, caps size at 25 MB, limits three files per request id, scopes the pathname to `ask-summit/{requestId}/`, and sets private access (AC2). The random suffix means a second upload of the same name never overwrites the first and no pathname is guessable.

### 3.2 The submit route (`POST /api/ask-summit/submit`), exact order

1. `startedAt`. Parse JSON (400). Honeypot: a non-empty `nickname` answers `{ ok: true }` and stores nothing.
2. `isPaused()`: 503 `{ error: PAUSED_BODY }`.
3. Validate: `isAskRequestId(requestId)` (400 "Please reload the page and try again."); `validateWebsiteUrl(url)`; `validateCompanyEmail(email)`; `consent === true` (400 "Please agree to the retention line."); `name` and `company` trimmed to 120 characters; `files` an array of at most three `{ name, pathname, url }` with `isUnderPrefix` and a known extension (400 with the matching message). `emailHash = hashEmail(email)`.
4. Limiters: `getAskIpLimiter().limit(ip)` (429 `RATE_LIMIT_IP_MESSAGE`, `Retry-After: 86400`), then `getAskEmailLimiter().limit(emailHash)` (429 `RATE_LIMIT_EMAIL_MESSAGE`). Both run after validation so a malformed body spends no token, and before the blob reads so a loop costs one limiter call.
5. Blob verification: for each file, `headBlob(url)`; null (not found) answers 400 `UPLOAD_FAILED_MESSAGE`; the returned `pathname` must equal the submitted one and sit under the prefix; `size` 1 to `MAX_FILE_BYTES`; `contentType` acceptable. The stored `AskFile` uses the head's values and the client's display `name` (trimmed, 200 characters).
6. Record: `createAskRequest` with `state: queued`, `createdAt`, `consentAt` now, `deleteAt = deleteAtFor(createdAt)`, `attempts: 0`, the rest null or empty. `AskRequestExistsError` (a replayed id) answers 409 "This request was already sent." and nothing else is written.
7. Enqueue: `enqueueProcessing(id, originFromHeaders(req.headers))`; on success HSET `enqueuedAt`, `enqueueMessageId`; on failure (unconfigured or an error) HSET `enqueueError` and `notifyAnthony({ kind: "stuck" })` inside `after()`. Nothing is lost either way (AC3).
8. Confirmation: `sendConfirmation(record, { origin, timeoutMs: min(10 s, 58 s − elapsed) })` with the delete link from `issueDeleteToken(emailHash)` (null when `UNLOCK_SECRET` is unset: the email carries the contact fallback and a warning is logged once); HSET `confirmationStatus`.
9. `void track("ask_submitted", { requestId, host, files: n, enqueued: boolean })`. No email or hash in the event.
10. Respond 200 `{ ok: true, requestId, site: host, files: names, confirmationSent }`. Blob URLs and pathnames are never in the response (AC2).

Any Redis failure in steps 6 to 8 is logged (addresses redacted) and answers 500 "Something went wrong. Please try again."; the orphan sweep removes the uploaded blobs if the record was never written.

### 3.3 The processing route (`POST /api/ask-summit/process`), exact order

1. `startedAt`. `rawBody = await req.text()`. `verifyQueueSignature(req, rawBody)`: `"unconfigured"` answers 503 `{ error: "QStash signing keys are not set" }` (logged; never processes unsigned); `"invalid"` answers 401. The URL passed to `verify` is the route's absolute URL from `originFromHeaders` plus the pathname.
2. Parse `rawBody` as JSON for `requestId`; `isAskRequestId` else 200 `{ skipped: "bad id" }` (logged; a retry cannot help).
3. `getAskRequest`; missing answers 200 `{ skipped: "unknown" }` (logged).
4. `state` `done` or `failed`: 200 `{ skipped: state }`. `state` `processing` and not stale: 200 `{ skipped: "processing" }`. `isPaused()`: 200 `{ skipped: "paused" }` and the record is left `queued` (the queue's Process now resumes it; decision 4.8).
5. `claimProcessing(id)` false: 200 `{ skipped: "locked" }`.
6. `void track("ask_processing", { requestId, attempt })`.
7. `outcome = await processRequest(id, { origin, startedAt })` inside try; the function never throws past its own boundary (every stage failure is recorded inside it); a throw here (a bug) is caught, recorded as `failed` at stage `finish` with the message, and answered 200.
8. `finally`: `releaseProcessing(id)`.
9. Respond 200 `{ ok: true, state: outcome.state, stage: outcome.failedStage ?? null, timings }`.

QStash retries (capped at 2 on publish) therefore only matter when the platform itself failed to run the route (a 5xx before step 1, a cold start timeout, a 504 from a function killed at 300 s); every handled outcome answers 200 so a retry never reprocesses a request already done or failed (AC4). A function killed at 300 s leaves `processing` with the lock expiring at 360 s; the retry that arrives inside that window answers `locked`, a later one answers `processing` until the 15 minute stale rule lets the queue's Process now reclaim it. The clock's 290 s budget is what keeps this path theoretical.

### 3.4 Stage (a): crawl (`crawlSite`)

Inputs: the start URL, `deadlineAt` (now plus the clock's allowance), the user agent from `ASK_SUMMIT_USER_AGENT` or the default.

1. Fetch `{origin}/robots.txt` with a 10 s timeout and the user agent; 200 text is parsed with `parseRobots`; 404 or any error means `robots: "missing"` or `"error"` and allow everything (a site without robots has not asked for anything). When `crawlDelayMs` is above zero the concurrency is 1 and each fetch waits that long after the previous one.
2. Frontier: a list ordered by score, seeded with the start URL at score 100. Visited set by normalised URL. Workers (`CRAWL_CONCURRENCY`, or 1 under a crawl delay) take the highest-scored unvisited URL while pages fetched < 40, `totalChars` < 1.5 MB and `Date.now()` < `deadlineAt` − 10 s (so a started fetch can finish inside the budget).
3. Per URL: `isAllowed(rules, path)` else count `disallowed`; `fetch` with `AbortSignal.timeout(PAGE_TIMEOUT_MS)`, `redirect: "follow"`, headers `user-agent` and `accept: text/html`; after the response, `isSameHost(res.url, start)` else count `offHost`; `content-type` must contain `text/html` else `notHtml`; `content-length` above `PAGE_BODY_CAP` else `notHtml`; read the text and cut at `PAGE_BODY_CAP`; `stripVisibleText`; a page whose text is under 40 characters is counted `duplicate`-free but not stored (empty shells); a text already seen (identical first 2,000 characters) counts `duplicate`; otherwise push `{ url: res.url, path, title, chars, score: scorePage(path, title), status, text }`, add `chars` to `totalChars` (when the cap would be passed the text is cut to fit and `truncated` is set, and the crawl stops after this page). `extractLinks` on the HTML, `normaliseLink` each, score by path, add unvisited ones to the frontier. A thrown fetch (timeout, DNS, TLS) counts `timedOut` or `failed` and never fails the stage.
4. Return the `CrawlStore` with `pages` sorted by score descending, the start page first regardless. Zero pages is not a failure of the stage: the start URL's own failure is recorded in `skipped` and the extraction proceeds with whatever documents exist (the draft then comes back thin). The stage fails only on a thrown programming error or the clock.

No JavaScript rendering, no form submission, no query strings beyond the start URL, no cookies, no authentication headers.

### 3.5 Stage (b): documents (`readDocuments`)

For each `AskFile` in order, inside the stage's allowance (each download with `AbortSignal.timeout` of the lesser of 20 s and the remaining allowance): `readBlob(url)` to a `Uint8Array`; a failure marks the entry `rejected` with "could not be downloaded"; `sniffFileType(bytes, name)` null marks `rejected` with "not a {expected type}" (the magic bytes check, AC1); `pdf`: when `bytes.length` exceeds `MODEL_FILE_MAX_BYTES` or the running PDF total would exceed `MODEL_FILES_MAX_BYTES`, mark `skipped` with "too large for the model" and set `pdfDropped`; otherwise keep the bytes in memory for the extraction call and store the entry as `status: "pdf"` with `chars: 0`; `docx` and `pptx`: `extractDocxText` or `extractPptxText`; an `OfficeTextError` marks `rejected` with its message; success stores `status: "text"`, the text, `chars`, `parts`, `truncated`. `saveDocs(id, { files })`. `docCount` is the number of entries with status `text` or `pdf`. The stage never fails on a bad file; three rejected files and zero pages still reach the extraction, which then returns empty parts (risk 7.9).

### 3.6 Stage (c): extraction (`draftParts`)

1. `material = { host, pages: pages with text, docs: entries mapped to text, pdf or rejected }`; `user = buildExtractionUser(material)`.
2. `files` = the kept PDFs as `{ name, mediaType: "application/pdf", data: base64 }`.
3. `callModel({ routingKey: "extraction", runId: null, requestId, system: EXTRACTION_SYSTEM_PROMPT, user, files, schema: extractionSchema(), parse: parseExtraction, temperature: 0 })`, raced against the stage allowance exactly as the 3a synthesis race (a timer that rejects with `StageTimedOutError("extraction", "the extraction overran its allowance")`; the model call is left to settle and is logged by `llm.ts`).
4. When the call throws and `files` was non-empty and the remaining allowance is at least the extraction minimum, retry once with no files and the PDF entries rewritten as `[Document: {name}, not readable: not sent to the model]`, setting `pdfDropped` (the PDF-over-limit and page-count cases, risk 7.7). Otherwise the stage fails with the error's message.
5. Build the `AskDraft` (`companyName` from the answer or `host` when empty, `summary`, `parts`, `model`, `sources`, `materialChars`); `saveDraft`.

### 3.7 `processRequest(requestId, { origin, startedAt })`, the six stages

`clock = createStageClock(startedAt)`. Each stage: `clock.allowance(stage)` (a `StageTimedOutError` here names the stage that could not start), `clock.start`, the work, `clock.finish`, and the record is updated with what the stage produced as soon as it finishes, so a later failure leaves the earlier results visible in the queue and the editor.

- (a) crawl: `crawlSite`; `savePages`; HSET `pageCount`.
- (b) documents: `readDocuments`; HSET `docCount`, `pdfDropped`.
- (c) extraction: `draftParts`; HSET `companyName`, `confidence` (per part), `extractionModel`, `pdfDropped`.
- (d) scoring: `parts = partsForScoring(draft.parts)` (the placeholder rule); `scoreModel({ parts }, { source: "ask-summit", requestId, deadlineAt: now + allowance })`; HSET `runId`. `InputError` cannot occur (the placeholder rule guarantees the lengths); `RubricNotPublishedError`, `NoToolsAvailableError`, `SynthesisFailedError`, `LlmNotConfiguredError` and child failures fail the stage with their messages.
- (e) report: `createReport({ slug: placeholderSlugFor(runId), company: companyName, runId, asOf: todayIso(), rows: mergeRows(run.rows), opening: summary || PLACEHOLDER_TEXT, productThoughts: PLACEHOLDER_TEXT, moonshot: PLACEHOLDER_TEXT, askRequestId })`; `SlugTakenError` (the same run already has a draft, impossible on a fresh run but handled) reuses that slug; `persistRunForReport(runId, childIds)` (a failure is logged); `void track("report_created", { slug, askRequestId })`; HSET `reportSlug`.
- (f) finish: HSET `state done`, `finishedAt`, `timings`; `void track("ask_processed", { requestId, runId, reportSlug, pages, docs, confidence, ms })`; `notifyAnthony({ kind: "done", ... queueUrl: {origin}/admin/ask-summit, editorUrl: {origin}/admin/reports/{slug} })` awaited with a 10 s transport budget (the function is alive; there is no response to delay).

Any stage failure: HSET `state failed`, `failedStage`, `failedMessage` (`redactAddresses(message)` cut to 300), `finishedAt`, `timings`; `void track("ask_failed", { requestId, stage, ms })`; `notifyAnthony({ kind: "failed", ... })` awaited with the same budget. The outcome `{ state, failedStage, timings }` goes back to the route. The request's `runId` from a scoring stage that completed before a report failure is kept, so Anthony can create the report by hand from `/admin/reports/new`.

### 3.8 The rerun route (`POST /api/admin/ask-summit/rerun`), exact order

1. `startedAt`. `validateSession` (401 JSON). `req.formData()`; `slug` passes `isValidSlug` (404 JSON); `askRequestId` passes `isAskRequestId` (303 to the editor with `error=rerun-mismatch`).
2. `getReport(slug)` missing: 303 `/admin/reports?status=not-found`. `report.askRequestId !== askRequestId`: `rerun-mismatch`. `getAskRequest`, `getDraft`: missing: `rerun-mismatch`.
3. `claimProcessing(askRequestId)` false (the lock, so a double click or a queued reprocess cannot race it): `rerun-busy`. From here the lock is released in `finally`.
4. `edits` = the five `part:{key}` fields as strings; `parts = partsForScoring(draft.parts, edits)`; `validateParts({ parts })` not ok: `rerun-invalid` (only reachable through a bug, since the placeholder rule guarantees the lengths).
5. `scoreModel({ parts }, { source: "ask-summit", requestId: askRequestId, deadlineAt: startedAt + 57,000 })`; any throw: logged, `error=failed`.
6. `rows = mergeRows(run.rows)` (all `edited: false`, originals from the new run); `saveReport(slug, { runId: run.id, rows, ...recomputeTotal(rows), updatedAt })`; `persistRunForReport`; `updateAskRequest(askRequestId, { runId: run.id, previousRunIds: [...previous, oldRunId], confidence unchanged })`; `saveDraft` with each part's `editedText` and `editedAt` set to the posted text when it differs from the drafted text; `void track("ask_rerun", { requestId, runId, previousRunId, slug })`.
7. 303 to `/admin/reports/{slug}?status=rerun`. The status line says the rows were reset and prior grade and comment edits are not kept (AC5); the three written sections are untouched because the patch does not carry them.

The route restores the previous state (`processing` → `done`) on the request record only through the lock release; the record's `state` is not changed by a rerun (it stays `done`).

### 3.9 The admin request route (`POST /api/admin/ask-summit/[id]`)

`validateSession` (401 JSON); `isAskRequestId` (404 JSON); `getAskRequest` missing: 303 `/admin/ask-summit?error=not-found`; `action` from the form:

- `process`: allowed for `queued`, `failed`, and `processing` when stale; else `not-queued`. HSET `state queued`, `failedStage null`, `failedMessage null`, `enqueueError null`; `enqueueProcessing(id, origin)`; failure: HSET `enqueueError` and `error=enqueue-failed`; success: HSET `enqueuedAt`, `enqueueMessageId`, `status=enqueued`. A stale `processing` record's lock is deleted first (`releaseProcessing`) so the claim succeeds.
- `delete`: `deleteBlobs(file urls)` (a failure is logged; the sweep catches the blob later); `deleteRequestData(id)`; `void track("ask_data_deleted", { requestId, reason: "admin" })`; `status=data-deleted`. The record, the draft, the run and the report are kept (AC6).

### 3.10 The retention cron (`GET /api/admin/ask-summit/retention`)

1. `CRON_SECRET` check as the daily report (401 on mismatch; when unset the route runs, as the daily report does).
2. `ids = listAskRequestIds()`; for each, `getAskRequest`; when `isDue(deleteAt, now)` and not `dataDeleted`: `deleteBlobs(file urls)` (logged on failure, continue), `deleteRequestData(id)`, `void track("ask_data_deleted", { requestId, reason: "retention" })`, count it. The request record stays with `dataDeleted: true` (AC7).
3. Orphan sweep: `listBlobs("ask-summit/", cursor)` page by page (at most 1,000 blobs per run to stay inside `maxDuration = 60`); for each blob whose `requestIdFromPathname` names no existing `ask:{id}` (one HEXISTS per distinct id, cached across the loop) and whose `uploadedAt` passes `isOrphanCandidate`, delete it; blobs belonging to a request already `dataDeleted` are deleted too (a blob the earlier delete missed).
4. Respond `{ ok: true, deleted, orphans, scanned }`. Redis down: 500 `{ error: "Redis unavailable" }` as the daily report.

The cron runs at 01:30 UTC daily (`vercel.json`); the daily report stays at 00:00.

### 3.11 The spend alert (inside `GET /api/admin/daily-report`)

Before the lead digest's zero-lead early return: `month = monthKey(now)`; `spend = getMonthSpend(now)`; `threshold = getSpendThreshold()`; `alerted = wasSpendAlerted(month)`; when `spendAlertDue({ spend, threshold, alerted })` and SMTP plus `NOTIFY_EMAIL` are configured: `sendMail` from and to `NOTIFY_EMAIL` with subject "Summit: model spend this month passed the threshold" and a plain text body ("Spend so far in {month}: ${spend}", "Threshold: ${threshold}", "Pause Ask Summit at {origin}/admin/ask-summit if this is unexpected", "Routing table: {origin}/admin/models", and the note that the figure comes from the last 2,000 logged calls); on success `markSpendAlerted(month)` (ISO now). The outcome is `spendAlert: "sent" | "failed" | "not-due" | "unconfigured"` on the route's JSON. A failure to send is logged and does not set the flag, so the next day retries. The lead digest then proceeds exactly as today. Once per month is enforced by the flag; the threshold is read fresh each day so a raised threshold after an alert does not re-alert until the next month (decision 4.11).

### 3.12 The state machine and idempotence

```
queued ──claim──▶ processing ──all stages──▶ done
   ▲                  │                        
   │                  └──any stage fails──▶ failed
   │                                          │
   └──────── Process now (also from stale processing) ◀┘
```

- `queued`: written by submit and by Process now. Carries `enqueueError` when QStash did not take the message.
- `processing`: entered only through `claimProcessing` (the lock plus HINCRBY `attempts`). Stale after 15 minutes without `finishedAt`; the queue shows it and allows Process now, which releases the lock first.
- `done`: terminal for processing. A rerun keeps `done` and only changes `runId`, `previousRunIds` and the draft's `editedText`.
- `failed`: terminal until Process now. `failedStage` and `failedMessage` are cleared when re-queued.
- `dataDeleted` is orthogonal: any state may have it; a `queued` or `failed` request with `dataDeleted` cannot be processed (Process now answers `not-queued` with the line "Its data was deleted") because there is nothing to read.

Idempotence under QStash: the route is safe to call any number of times for one id; only the first call that wins the lock on a `queued` (or stale) record does work; every other call answers 200 without side effects beyond a log line. Within a run, each stage overwrites its own keys (`pages`, `docs`, `draft`), so a reprocess after a failure starts clean; a reprocess after `done` is refused, so one request produces at most one report from processing (reruns reuse that report).

### 3.13 Delete-my-data for requests

The 1b delete route's POST, after `deleteRunsByEmail`, calls `deleteAskRequestsByEmail(hash)`: the route first reads the ids and their file urls (through the store), `deleteBlobs` for all of them (logged on failure), then the store removes the records, the data keys, the drafts, the index entries and the set. Composite runs created from those requests are not touched (they are not in `runs:by-email`, there was never an unlock) and nor are the reports (AC7 and decision 4.9). `ask_data_deleted` is tracked per request with `reason: "delete-link"`, and `data_deleted` carries `requests: m` beside `count`.

### 3.14 `scripts/process-ask.ts`

Usage `npm run process-ask -- {requestId}`; exit 2 without an id or when the Upstash, OpenRouter and Notion variables are missing (never printing a value); lazily imports the store and `processRequest` after the check as `calibrate.ts` does; `claimProcessing` false prints "locked or already processing" and exits 1; otherwise runs `processRequest` with `origin` from `SITE_ORIGIN` or `http://127.0.0.1:3000`, prints the outcome (state, stage, timings, report slug), releases the lock, exits 0 on `done` and 1 on `failed`. The same code path as the route minus the signature, so a local run exercises every stage.

## 4. Key Decisions

1. **Direct-to-Blob client uploads with a server token, the id minted by the browser.** Alternative: multipart POST to the submit route. Rejected: Vercel's 4.5 MB request body cap. The id is minted on the client so uploads can start before submission (AC2); the server validates its shape everywhere, scopes the token to its folder, counts files per id, and claims it with HSETNX at submit so a replay cannot overwrite a record. The browser never sees a blob URL after submit: the response carries names only, the confirmation email carries none, and the admin pages are behind the session.

2. **Magic bytes are checked when the server first holds the bytes, in the document stage.** Alternative: download each blob at submit to sniff it. Rejected: up to 75 MB through the submit route for a check that the document stage performs anyway minutes later, and the submit route must stay inside 60 s. The submit route checks the extension, the stored size and the content type from `head()`; the document stage sniffs and rejects with a reason the editor shows. Assumption flagged against AC1's wording.

3. **One extraction call with the PDFs as file inputs, native engine, text-only fallback.** Alternative: `pdf-text` engine (free, text only) throughout. Rejected: decks are often image-heavy and the native engine lets the model read them; the cost is bounded (a 30 page deck is roughly 45,000 input tokens, about $0.15 on the default Sonnet route). The fallback to text only exists because the native path has limits the server cannot check in advance (page count, risk 7.7). The temperature is 0 so a rerun of the same material drafts the same parts.

4. **The extraction prompt lives in code.** The owner has not written a Notion row; `getRubric` reads Published rows only and a missing row would fail the stage. The constant sits in one pure module with the schema beside it, is tested for the house rules, and the runbook names the move to a `ask-summit-extraction` row (read through `getRubric` with a code fallback) as the follow-up.

5. **Same host after stripping one leading `www.`.** `example.com` and `www.example.com` are one site to every visitor and most sites redirect one to the other; a strict comparison would stop the crawl at the redirect. Subdomains (`blog.`, `docs.`, `app.`) are different hosts and are not followed. Assumption flagged.

6. **robots.txt as prefixes only, longest match wins, allow on a tie.** The brief asks for allow and disallow prefixes; `*` and `$` are not interpreted (a pattern is cut at its first `*`), which errs toward obeying a disallow. `Crawl-delay` is honoured up to 5 s because a site that asks for it is exactly the kind that will block an impolite crawler. The product token is `SummitBot`; the full user agent names the page the crawl serves.

7. **Processing route answers 200 for every handled outcome; QStash retries cover platform failures only.** Alternative: 5xx on a stage failure so QStash retries. Rejected: a crawl that failed on a dead site or an extraction that returned nothing will fail the same way in two minutes, and the retry would spend another model call; the admin queue's Process now is the retry, with a person deciding. `retries: 2` stays on the publish so a cold start or a killed function is retried, and the lock plus the state check make those retries harmless.

8. **The pause switch stops intake and processing; resume does not auto-enqueue.** The switch is the manual response to a spend alert, so it must stop spend, which means the processing route must honour it too. A paused request stays `queued` and the queue lists it with Process now; after resuming, Anthony presses it per request. An auto-resume loop (re-enqueue every queued request on resume) is the obvious follow-up and is out of scope. Assumption flagged.

9. **Retention and the delete link remove the raw material; the draft, the run and the report stay.** The spec's retention covers uploads and crawled pages, and the delete link covers "requests" while touching "nothing of the report". The draft and the composite run hold the drafted parts, which are Summit's derived work and what the report is built on; deleting them would hollow out a report Anthony may have already sent. The consent line therefore promises deletion of the pages and files, which is what is deleted. The delete link removes the request record too (the spec says so) while retention keeps it with `dataDeleted`. Flagged for the owner (risk 7.12).

10. **A two day backstop expiry on the pages and docs keys.** The cron is the mechanism; EXPIREAT at `deleteAt` plus two days means a cron that is never configured still cannot keep crawled text beyond 32 days, and the two day gap lets the cron set `dataDeleted` first in the normal case. Blobs have no such backstop (the sweep is the only mechanism), which is noted in the runbook.

11. **The spend alert is a separate daily-report email, once per month, from `ai:calls`.** It runs before the zero-lead early return so a quiet day still alerts; it is its own email rather than a line inside the digest because the digest is skipped on quiet days. The month is UTC and the flag is per month, so a threshold raised after an alert waits for the next month. `ai:calls` is the only cost record the site has; its 2,000 entry cap is a known limit (risk 7.14).

12. **The honeypot is named `nickname`, not `website`.** The 3a pages use `website` as the honeypot because they have no real website field; this form's main field is a website address, and a browser's autofill could put the visitor's site into a hidden `website` input, turning a human into a silent no-op. A field no form would ask for avoids it.

13. **A failed upload abandons the request id.** A retry after a failed upload mints a new id so the token count and the folder start clean; the blobs under the abandoned id are orphans and the sweep removes them after 48 hours. Alternative: reuse the id and let the submit route tolerate extra blobs. Rejected: the three-per-id count would have to be reset through the server.

14. **The rerun route resets the rows and says so.** The spec rules out merging edits where the grade differs; a half merge (keep edits where the grade matches) would hide which rows are Anthony's and which are the model's. All five rows become the new run's with `edited: false`; the status line says the edits were not kept; the three written sections are not touched.

15. **Ask Summit composites are admin only on the 3a surfaces.** The result page, the details route and the OG image are public by run id; a leaked id would show the raw run, which the spec forbids. The page and the details route require the admin session for a `source: "ask-summit"` run (Anthony needs them to store the working the report shows), and the edge image, which cannot read the session, always draws the empty frame for one. The prefill endpoint is unchanged: a child's inputs are the drafted parts, which the published report's re-run links already hand to the prospect by design (Release 4).

16. **`requestId` is threaded through `scoreModel` and `PipelineContext` as a tag.** The spec puts `requestId` on calls "made by processing"; the scoring and synthesis calls are made by processing through `scoreModel`. Passing an optional id through two context types to `callModel` changes no prompt, stage, store field or event, so it sits inside "accepting `source: "ask-summit"`" in spirit; the alternative (join on `runId` through the request's `runId` and the composite's `children`) is kept as the fallback if the Reviewer objects.

17. **`callModel` grows two optional arguments.** AC8 wants `llm.ts` unchanged beyond the log field; the constraint that every model call goes through `callModel` and the owner's choice to send PDFs to the model natively leave no other place for the file parts to be built. The additions are guarded (extraction key only, size caps) and every existing caller is unaffected. Flagged as the one deviation from AC8's wording.

18. **The admin queue and the rerun are plain form POSTs; the models page gets one small panel.** As Release 4: server pages, 303 redirects with status codes, `validateSession` first. The spend threshold is written through its own route rather than the models PATCH handler, whose first act is to validate a routing key.

Assumptions collected: 2, 5, 6, 8, 9, 16, 17, plus: the consent checkbox is required (the spec says "a consent line"; a line nobody ticks gives `consentAt` nothing to mean); the queue email is `email` in clear on the record and the queue (AC3 lists it) but never in a log or an event; the free-mail list is the one in 2.1 and is easily extended; the crawl's 40 pages are fetched pages, not discovered links; the extraction text budget is 160,000 characters (roughly 40,000 tokens) so that the five scoring children (which read the drafted parts, not the material) stay cheap and the one extraction call stays well inside the context window; `maxDuration = 300` is set on the processing route and the owner confirms the Pro plan before deploy (risk 7.1); the retention cron runs at 01:30 UTC; the orphan age is 48 hours.

## 5. Constraints Honoured

- **Dependencies limited to `@vercel/blob`, `@upstash/qstash` and `fflate`; no PDF library.** `package.json` gains exactly those three at exact versions and one script. PDFs reach the model as file parts through `callModel`; no parser is installed. Gate F greps confirm each package is imported in one server module (`blobs.ts`, `queue.ts`, `office-text.ts`) plus the client upload helper in `AskSummitPage.tsx`.

## 7. Risks and edge cases for the Reviewer

1. **Vercel Pro and 300 seconds.** `maxDuration = 300` is refused at build or capped at deploy on the Hobby plan. The owner confirms the plan before the Phase D preview; the runbook states the requirement. With Fluid Compute enabled the default ceiling is higher still, but the route pins 300 and the clock pins 290.

2. **QStash retries and idempotence.** Every handled outcome answers 200, so retries fire only on platform failures; the lock (6 minutes) plus the state check make a retry harmless; a function killed at 300 s leaves `processing` until the 15 minute stale rule. The Reviewer should confirm the route reads the raw body before parsing, releases the lock in `finally`, never answers 5xx after the claim, and that `claimProcessing` sets `attempts` with HINCRBY.

3. **QStash cannot reach localhost or a protected preview.** Local runs use `npm run process-ask`; previews need `VERCEL_AUTOMATION_BYPASS_SECRET` passed as the `x-vercel-protection-bypass` header on publish. Without either, the request is stored with `enqueueError` and the queue shows it. The end to end check in Gate D needs a deployed host.

4. **Blob token scoping and leakage.** The token is scoped by pathname prefix, content type, size, validity (15 minutes) and the per-id count; the random suffix defeats guessing. The Reviewer should check `onBeforeGenerateToken` rejects a pathname with a second slash or `..`, that the submit route trusts `head()` and not the client for size and type, and that no response, email, event or log carries a blob `url`, `downloadUrl` or token.

5. **Private access in `@vercel/blob` 2.8.2.** The design assumes `access: "private"` on `upload` and a server read helper. If the installed SDK lacks either, the fallback is public access with random suffixes and URLs that never leave the server; the Coder records the change in the runbook and the Reviewer checks the grep for `downloadUrl` across responses still returns nothing.

6. **Sites that block bots or need JavaScript.** Cloudflare challenges, 403s for unknown agents, and single-page apps return little or no visible text; the crawl then stores few pages, the draft comes back thin, and the placeholder rule carries the run through with low confidence. The queue shows `pageCount` and the editor the page list, so Anthony sees it. Nothing retries a blocked site.

7. **PDFs over the model's limits.** The size guard (20 MB per file, 30 MB combined) prevents the base64 request from exceeding the provider's request cap; the page count (Anthropic's 100 pages) cannot be checked without a parser, so a long deck fails the first extraction call and the text-only fallback runs when the allowance permits. The Reviewer should confirm the fallback is attempted at most once and that `pdfDropped` is set and shown in the editor.

8. **DOCX and PPTX that are images only.** The extractor returns almost no text; the entry is `text` with a small `chars` and the draft is thin. The editor's document list shows the character count so it is visible; converting to PDF and resubmitting is the operator's workaround and the runbook says so.

9. **The extraction returning five empty parts.** Allowed by the schema and the parser; the placeholder rule turns each into a placeholder so `scoreModel` runs and every child scores 1s; the report is created with the host as the company and a thin summary. The queue's confidence summary reads "0 high, 0 medium, 5 low". The Reviewer should check nothing in the chain throws on `text: ""`.

10. **The spend alert's reliance on `ai:calls` cost fields.** `cost` is null when OpenRouter omits usage cost (some providers and the fallback model path); such calls count as zero, so the month's figure is a lower bound; the alert email says so. See also 14.

11. **The editor rows reset on rerun.** By design (decision 14); the status line says it, the section's own line says it before the button, and the three written sections survive. The Reviewer should confirm the rerun patch carries `runId`, `rows` and the totals only, and that `report.askRequestId` must match the posted id.

12. **Derived data after deletion.** Decision 9: the draft, the run and the report outlive the raw material. The owner should confirm the consent wording ("the pages we read and the files you upload") matches what is deleted, and decide whether a delete-link request should also unpublish a report that names the company.

13. **`scale-up-advisory.test.ts` must stay byte identical.** It imports `sitemap.ts`, which gains one URL no assertion excludes. Every gate diffs it against `main`.

14. **`ai:calls` is capped at 2,000 entries.** One Ask Summit request is about nine calls; a busy month could exceed the cap and the month's spend would be undercounted. The alert body states the basis; raising the cap is a one-line change in `llm.ts` left to the owner.

15. **`callModel` cannot be cut short.** Both the extraction and the synthesis are raced against the clock; an abandoned call keeps running until the function freezes and is logged when it settles, as in 3a. The Reviewer should confirm the timer is cleared when the call wins and that a late rejection is caught.

16. **Memory in the processing function.** Three 25 MB files plus their base64 copies plus the crawl text can approach 200 MB; the default function memory is 1,024 MB on Pro. PDF bytes are discarded after the extraction call. The Reviewer should check the document stage does not hold text and bytes for rejected files.

17. **Crawl text budget versus extraction budget.** The crawl stores up to 1.5 MB; the extraction sends at most 160,000 characters, trimming the longest pages first. A site whose important text sits on a long page can lose its tail; the page list in the editor shows which pages were read and the `[cut]` marker shows what was trimmed.

18. **The free-mail refusal and the rate limit by email.** A prospect using a company address that is actually a free-mail custom domain passes; a prospect at a company whose domain is on the list (Google, Microsoft, Apple, Proton, Yahoo staff) is refused. Acceptable and noted; the message names the contact address.

19. **Two consent surfaces.** The consent line is on the form (ticked) and repeated in the confirmation email; the record stores `consentAt`. The checkbox is an assumption (section 4); the Reviewer should confirm the submit route refuses `consent !== true`.

20. **Admin session on the 3a result page.** `validateSession` reads the `admin_session` cookie (path `/`), so Anthony's browser passes on `/tools/built-to-scale/r/{id}`; logged out, the page 404s for an ask-summit run. The details route uses `validateSession` from `next/headers` inside a route handler, which Next 16 supports; the Reviewer should check a private window gets 404 from both.

21. **`listAskRequests` and `countAskRequestsByState` scan the whole index.** Fine at tens to hundreds of requests; the dashboard card reads the list once per render. A paginated count is a later change if the queue grows past a thousand.

22. **Preview smoke before merge.** With Blob, QStash, OpenRouter, Notion (row Published), Upstash, SMTP and `UNLOCK_SECRET` set on a preview with the bypass secret: a real submission with a PDF and a DOCX; the confirmation email and its delete link; the processing within five minutes and the "ready to review" email; the editor's drafted inputs and a rerun; the queue's Process now on a forced failure; the retention route on a request with a past `deleteAt`; the spend alert with a low threshold; the paused state on the form, the token route and the submit route; the result page 404 for the run in a private window; the form at 375 px wide with no horizontal scroll.
